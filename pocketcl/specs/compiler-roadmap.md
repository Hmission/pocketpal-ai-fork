# PocketCL T3：编译器路线规格（compiler-roadmap v0.1）

> 定位：把 T0-T2 的手动内核优化经验程序化——评估并设计「编译器自动化」替代/增强手写内核的路线。
> 基准：2026-08-29。上游参照：TVM/MLC-LLM/AutoTVM、llama.cpp 社区讨论。
> 现状：T0 资产 ✅ / T1 API ✅ / T2 探针 ✅ / T4 回馈备料 ✅ —— T3 是本路线图最后一个阶段。

## 1. 目标与边界

**目标**：热点算子的调优从「人工逐内核手调」走向「搜索空间 + 自动调参」，输出与手动基线同等质量
（性能 ≥ 手动 95%、nan=0、多设备分级正确）。

**边界（锋利不重造）**：
- ❌ 不引入新运行时（TVM 生成 OpenCL 内核，仍走厂商驱动/OpenCL 管线执行）；
- ❌ 不做整图编译替换（MLC 整链路为远期评估，不是第一验证对象）；
- ✅ 复用一切既有资产：CLPROF 榜单（搜索种子/评估器）、设备卡（编译约束）、
  patches 手动基线（对照物）、PocketCL API（策略消费）。

## 2. 现状基线（手动战绩 = 编译器路线必须打败的门槛）

| 资产 | 手动成果 | 对照门槛 |
|---|---|---|
| Mali 半精度 tiled GEMM | 2.86-3.42×，nan=0 | 编译器同算子 ≥ 手动 95% |
| Adreno XMEM GEMM | 3.6×（Z-Image 全链路） | 需设备卡 tier2 + xmem 扩展 |
| tiled VAE | 1.94GB→416MB | 内存类收益编译器难自动复刻 → 维持手动 |
| CLPROF 探针 | top-N 榜单 | **搜索空间的评估器** |

## 3. 路线三选（决策）

| 选项 | 描述 | 收益 | 风险 | 判定 |
|---|---|---|---|---|
| **A. 单算子 TVM 替换** | 仅热点 GEMM（CLPROF 71%+）用 TVM 搜索空间生成内核，其余维持手动 | 增量验证、风险隔离、复用 CLPROF 闭环 | TVM 对 Mali/Adreno 驱动兼容性未知；首次排期 | ✅ **起步路线**（本规格主体） |
| B. MLC 整图编译 | 端侧全图编译（MLC-LLM 范式） | 全局最优理论 | 端侧编译产物大、驱动兼容未知、与 sd.cpp 集成成本高 | 远期评估（T3.3） |
| C. 维持手动 + CLPROF 闭环 | 现状 | 稳定 | 人力密集型，扩展慢 | 保底（不退化线） |

## 4. T3 分阶段

### T3.1 可行性预研（本规格 + 本地资产，零网络可完成大部分）

- 输出：热点算子清单（来自 CLPROF 榜单，top-N ≥ 70% 覆盖）；
- 输出：搜索空间定义（见 §5）——设备卡约束映射；
- 输出：编译环境选型（PC 交叉编译 → 设备运行；禁手机端编译）；
- 判定门：搜索空间可枚举且维度 ≤ 3，评估器闭环可模拟（CLPROF 结构已知）。

### T3.2 单算子替换试点（网络恢复/有 GPU 环境后）

- 对象：`mul_mm_q4_k_f32_l4_lm`（CLPROF 55.6% 单算子）；
- 方法：TVM 目标=OpenCL，搜索维度按 §5，评估器=CLPROF 榜单（同 T2 CLI 消费）；
- **胜出门槛**：≥ 手动基线 95% 且 nan=0、值域 ±5（铁律 3 回归）；
- 失败判定：搜索产物不达标 → 记录原因（驱动/编译器限制）→ 回落 C 并归档结论。

### T3.3 MLC 整链路评估（远期）

- 输入：T3.2 结论 + 端侧编译产物实测（体积/加载/耗电）；
- 判定：整图收益 vs 产物成本，产出 ADR 级备忘。

## 5. 搜索空间设计（T3.1 核心规格）

```
输入（种子）：CLPROF 榜单（算子名/形状/占比） + 设备卡（family/tier/exts/ramMb）
搜索维度（≤3）：
  D1 TM/TN tile 组合        ∈ {4x8, 5x8, 8x8}（继承 l4_lm 手动经验）
  D2 向量宽度 VEC           ∈ {4, 8}（Mali 建议 8；fp16 pipe 对齐）
  D3 unroll 因子            ∈ {2, 4}（local 带宽权衡）
约束（硬过滤，来自设备卡）：
  - Mali 且无 FP16_STORAGE    → 禁 half 域（D2 只能 4 + fp32 路径）
  - Adreno tier<2             → 禁 xmem 域（不搜 xmem 变体）
  - 设备卡 pending 项         → 该维度降级为通用档
评估（闭环）：CLPROF 榜单同一格式（T2 CLI 直接消费）→ 与手动基线对照
输出：最优 (tile, vec, unroll) 三参组 → 回注 policy（L3 tuning 先例）
```

## 6. 验收标准（T3 整体）

1. T3.1 交付：本规格 + 热点清单 + 搜索空间 JSON（机读，对齐 devices/schema 风格）；
2. T3.2 交付：单算子搜索结果 ≥ 手动基线 95%、nan=0、跨设备分级正确（K Pad/K90 各一）；
3. 全部产物走 pocketcl 三态诚实（搜索数据 = verified 需真机复测）；
4. 失败也验收：归档根因（驱动限制/编译器 bug/评估器缺陷），不硬凑成功。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| TVM 对 Mali/Adreno 闭源驱动内核生成兼容性差 | T3.2 前先做「最小内核编译冒烟」（hello GEMM），失败即判 A 路线不可行，回 C |
| 搜索成本（时间/能量） | 维度 ≤3 + 设备卡硬过滤 + 参数化随机采样上限 |
| 与 sd.cpp 构建链集成 | 生成 .cl 静态内嵌（GGML_OPENCL_EMBED_KERNELS 同类），不引入运行时依赖 |
| 铁律 3（fp32 累加）被编译器优化破坏 | 搜索空间强制累加器 fp32 约束 + nan 回归为硬门 |

## 8. 衔接（资产消费图）

```
T2 CLPROF 榜单 ──种子──> T3 搜索空间 ──约束──> 设备卡（T0）
        └──评估器──> T3 搜索结果 ──回注──> policy（T1）──> 引擎/CLI 消费
T4 patches 手动基线 = 对照物（胜出门槛的度量衡）
```

## 9. 本期结论

- A 路线（单算子替换）为本阶段唯一可行路线，风险可控、资产复用完整；
- T3.1 的本地实体（搜索空间 JSON + 热点清单）**零网络即可完成**，列为下一执行项；
- T3.2 依赖 GPU/编译环境（网络恢复或 PC 有 OpenCL 驱动），不阻塞其他路线。
